## ⚡ Featured: Easy Sys Admin

<a href="https://github.com/infinit3HQ/easy-sys-admin">
  <img src="https://raw.githubusercontent.com/infinit3HQ/easy-sys-admin/main/.github/social-preview.png" width="100%" alt="Easy Sys Admin: one board for the whole fleet"/>
</a>

**One board for a fleet of Linux servers.** Add servers, group them, and pick when each group gets its disks cleaned and its packages patched. The board shows live status, and AI agents can read the same data and start runs over MCP.

| Feature                 | What you get                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| 🔒 **Nothing listens**  | SSH as a locked-down `esa` user, or an outbound agent over HTTPS for servers behind NAT               |
| 📊 **Live status**      | CPU, memory, disks, inodes, failed units, Docker and pending reboots every minute, kept for 90 days   |
| 🩹 **Safe patching**    | Security-only or full updates in batches, stopping after a set number of failures, optional reboot    |
| 🧹 **Strict cleanups**  | Docker build cache, old VS Code servers, journal caps. Never volumes, never images in use             |
| 🔔 **Alerts**           | Disk, memory, certificates, unreachable servers and failed runs to Slack, Discord, ntfy, webhooks, email |
| 👥 **Teams**            | Organizations, roles, teams and groups shared across organizations                                    |
| 🤖 **CLI + MCP**        | One API behind the web app, the `esa` CLI and an MCP endpoint for agents                              |

## 🧭 How we build

- **Yours to run.** If it holds your data, you can host it yourself, with Docker and a short guide.
- **Open by default.** Source is public, and the self-hosted projects use AGPL-3.0 so they stay that way.
- **Small and strict.** Tools do one job, ask for the least access they need, and say what they changed.

## 🤝 Contributing

Every repo takes contributions. Pick one, read its README (and `CONTRIBUTING.md` where there is one), then open an issue or a pull request. Found a security problem? Don't open a public issue: follow the repo's `SECURITY.md`, or use GitHub's private vulnerability reporting.
